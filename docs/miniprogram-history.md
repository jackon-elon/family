# 人间星图微信小程序

基于[需求文档](./亲友关系网小程序需求文档.md)实现的本地演示版。产品暂名「人间星图」，家人和同窗分别记在「家人录」「同窗录」中。首次从「微信手机号登录」进入，以后在验证有效期内自动进入；本地演示用模拟号码，真实号码要接入云开发后由微信授权。底部是「亲友录」「我的」：前者分开展示家人录与同窗录，后者只有一份「我的资料」和按权限出现的管理入口。管理员管理具体记录；普通成员不会看到管理模块。家庭关系图按辈分分层，同辈同一行、本人高亮，点人物可看称呼与关系路径。列表和地图显示成员所在城市，世界视图还提供全球分布概览。已有测试小程序 AppID，尚无云开发环境 ID，默认运行演示数据。

管理员可添加家人或同学，也可通过微信分享或二维码邀请。家人录已有人的情况下，新增家人须选择一位已记录的人物，确定亲子、配偶或兄弟姐妹关系；只有首位家人可以先没有关系。管理页直接提供「编辑资料」「编辑关系」，管理员修改人物资料只影响当前这份记录，不会改动对方加入的其他记录。预录的核对手机号只帮助已获准加入的人匹配人物，不会因号码相同就自动加入一份记录。本人在「我的资料」维护一份账号资料，并同步到已关联的家人录和同窗录；管理员针对某份记录做的更正留在该记录内。首页人数按已记录的人物统计，与详情一致。受邀申请直接使用本人的账号资料，只另填身份说明。本人生日不出现在近期提醒；同一人在多份记录中的生日只提醒一次。阳历和农历生日每年换算下次公历日期，农历使用香港天文台 1901–2100 年公农历对照数据。城市从离线目录逐级选择；只记录城市，不读取实时位置。

## 本地验证

需要 Node.js 22。项目根目录执行：

```powershell
npm install
npm test
npm run build:cloud
```

`npm test` 运行亲属规则、关系图布局、后端权限、手机号登录与关联、共享资料、生日换算、照片访问和前端演示测试，以及 TypeScript、页面配置和云函数打包一致性检查。`build:cloud` 编译云端服务并将产物放入 `cloudfunctions/api/lib`。执行结果及未验证部分见[测试报告](./docs/test-report.md)。

安装微信开发者工具后，以**项目根目录**（本目录）导入 `project.config.json`。其中 `appid` 为占位值 `touristappid`；在 2.02.2609231 版开发者工具中，直接导入会报“不存在此 AppID”。本地已在被 Git 忽略的 `project.private.config.json` 配置测试 AppID；在其他电脑使用时可用自己的 AppID 创建同名文件：

```json
{"appid":"wx你的测试号"}
```

再次导入项目即可，不需要修改已提交的 `project.config.json`。演示数据保存在本地缓存，不需要云开发环境。云函数目录在项目根的 `cloudfunctions/`，因此不要只导入 `miniprogram/` 子目录。

关系图、地图、逐级城市选择、登录、统一个人资料、普通成员和生日页面的开发者工具模拟器截图与操作记录见[测试报告](./docs/test-report.md#微信开发者工具模拟器实测)；真机复核仍待进行。

## 目录

- `miniprogram/`：原生小程序页面、演示数据和云函数调用适配器。
- `backend/`：TypeScript 后端服务、内存仓库、CloudBase 仓库适配器及测试。
- `cloudfunctions/api/`：微信云开发事件函数入口与构建产物。
- `packages/kinship/`：独立亲属称呼引擎及规则测试。
- `packages/lunar-calendar/`：香港天文台公农历对照数据与前后端共用换算。
- `docs/`：[总体架构](./docs/architecture.md)、前端／后端设计、[测试计划](./docs/test-plan.md)与[入圈和管理流程产品复核](./docs/product-review-onboarding-and-admin.md)。

亲属称呼源文件在 `packages/kinship/src/index.ts`；`npm run sync:kinship` 将其复制到小程序可打包的 `miniprogram/vendor/kinship.ts`。农历换算源文件在 `packages/lunar-calendar/src/index.ts`，构建前会同步到前后端。

## 接入真实微信环境

账号主体需提供 CloudBase 环境 ID，再按[后端设计文档](./docs/backend-design.md)创建十五个集合，包括只由云函数读写的 `phoneMatches`、`phoneIdentities`、`userProfiles` 和 `personRemarks`，为每个集合配置**拒绝客户端直接读写**的规则并部署云函数。小程序只通过云函数读写私人资料；照片由服务端验证权限、剥离元数据并限制上传次数后保存。云函数 `api` 必须仅供该微信小程序事件调用，不能与 Web／HTTP 等来源共用。接入后还需用多个真实微信账号做邀请、权限、手机号授权与关联、照片和真机地图验收。

本地自动化测试通过不等于微信审核或云端安全验证通过。邀请页已接入云函数生成小程序码，扫码会进入同一份一次性邀请的申请页；本地演示模式明确提示不可生成真实码。当前缺少云环境 ID，因此小程序码的真实生成、扫码、跨账号审批和微信手机号能力仍需部署后验收。城市从[离线城市目录](./docs/city-catalog-data.md)逐级选择；目录外可填写城市，但地图会标为“待定位”。城市中心坐标只保留约 0.1 度精度，不读取实时位置。正式发布所需的账号、备案、隐私指引和提审由小程序主体在微信平台完成。
