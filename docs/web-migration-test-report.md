## 性能与轻量交互反馈（2026-10-05）

- 前端称呼改为一次授权数据快照内批量计算，共享数据校验、人物索引和关系图；人物详情复用同批结果。不建立全局跨账号缓存。搜索结果及亲缘图筛选使用memo与Set，避免选择人物时重做无关筛选与地图城市分组。
- SQLite增加按家庭/用户及ID排序的复合表达式索引；对应JSON路径使用固定白名单SQL表达式，参数值仍绑定，其他字段路径仍绑定。原来ORDER BY查询只使用collection，现查询计划使用collection与表达式值且不需临时排序。权限、家庭范围、5000条上限及事务逻辑保留。
- 可复现实验：`node scripts/benchmark-family-performance.cjs`，全程内存合成数据，不接触用户数据库。预热3次、采样15次的中位数：100人称呼逐人计算26.653ms，批量1.110ms；20000条人物记录中筛100条，一个SQL查询4.919ms降至0.054ms。这是本机单项耗时，不是页面或HTTP接口整体加速倍数。
- 普通头像延迟加载并异步解码，大头像及时加载；部署Caddy为带内容哈希的/assets文件启用一年immutable缓存，首页仍no-cache，受保护照片仍走API权限检查。当前环境没有Docker/Caddy可执行程序，缓存配置未在容器中实跑，重新部署后生效。
- 按钮加入120ms背景/边框反馈，弹窗与提示加入160ms透明度淡入；只在prefers-reduced-motion:no-preference下启用。不对整幅关系图或地图添加变换、滤镜或持续动画。
- 回归201/201，称呼引擎28/28，前端类型检查与构建通过。批量结果逐项比对原单人算法（含百人、多视角、冲突、无关系、自定义叫法、农历日期）；新增SQL索引计划、参数绑定、空值/布尔查询及修改后即时结果检查。
- 手机浏览器实测：名称/称呼搜索找到8位堂侄子，详情称呼与路径正确；照片带lazy/async属性，弹窗动画0.16s且filter为none；中国地图、亲缘图切换正常。现有临时测试服务已重启，数据库优化生效。[界面截图](preview/web-performance-person-mobile.png)。

- 浏览器做了上述关键流程抽查；更完整的邀请、权限和并发异常路径通过自动化集成测试验证，不把它们表述为全部逐项手动验收。
- 当前数据库部署为单个 API 实例，未验证多实例、负载测试或真实手机微信内置浏览器。
