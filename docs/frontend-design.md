# 微信小程序前端设计与本地演示

## 启动

小程序源代码位于 `miniprogram/`。用微信开发者工具导入项目根目录的 `project.config.json`，其中 `miniprogramRoot` 指向该目录，`cloudfunctionRoot` 指向根目录的 `cloudfunctions/`。演示模式默认开启，数据保存在当前开发者工具或设备的本地存储；首页可恢复初始样例。根配置中的 `touristappid` 是占位值，当前版本开发者工具需填入测试 AppID 才能在模拟器打开。

正式连接云端时，在项目根目录的 `project.private.config.json` 填入自己的小程序 AppID，并在 `miniprogram/config.ts` 填写 CloudBase 环境 ID，部署名为 `api` 的云函数。只有环境 ID 非空且 `wx.cloud.callFunction` 可用时，首页才允许切换云端模式。所有页面通过 `miniprogram/services/api.ts` 的 `invoke({action,payload})` 访问数据，成功返回 `{ok:true,data}`，失败返回 `{ok:false,error:{code,message}}`。云端权限必须由后端检查，页面上的按钮隐藏只服务于用户体验。

## 页面与操作

| 页面 | 用途 |
| --- | --- |
| 我的圈子 | 家庭圈和同学圈分组浏览、本人加入申请状态、建圈入口、演示/云端状态 |
| 新建圈子 | 选择圈类型、自己记录或邀请共建；同学圈必填学校、届别、班级 |
| 圈子首页 | 家庭关系图/列表/地图，同学列表/地图；搜索、筛选、点击人物查看关系；无本人卡时核对已有卡或明确新建 |
| 人物资料 | 称呼及解释路径、公开资料、联系方式、认领/更正入口 |
| 编辑人物卡 | 本人编辑资料和照片，未认领时提醒核对同名已有卡；管理员为未认领卡只填最少资料；受托人只编辑授权字段 |
| 选择城市位置 | 填写城市与国家，在微信原生地图上手动移动中心点并确认城市代表位置 |
| 管理圈子 | 分别管理邀请、未认领人物卡、成员账号；审核加入与认领、预览并更正关系、采纳结构化建议、解绑错误认领、查看操作记录 |
| 邀请加入 | 生成 72 小时一次性邀请，微信分享与小程序码共用令牌，支持撤销；本地演示不生成可扫码真码 |
| 申请加入 | 只显示有限圈信息，填写姓名和身份说明（同学圈需写同班核对信息），查看本人申请状态 |
| 资料可见范围 | 照片、城市、学校、行业、职业、状态、近况、电话和微信号逐项设置；长辈代维护授权与撤销 |

家庭圈关系图按辈分分行：亲子边的父母高一辈，兄弟姐妹和配偶同辈；本人高亮，点击人物查看该人物与本人的称呼和关系路径。关系矛盾或不连通的人物单列待核对。搜索只淡化非匹配节点，保留完整亲属链以免算错层级。称呼由共享 `packages/kinship` 引擎计算。构建/检查时 `scripts/sync-kinship.mjs` 将同一份源代码复制到 `miniprogram/vendor/kinship.ts`，前端适配器把后端 `parent/spouse/sibling` 边转换成引擎输入。资料不完整时展示引擎给出的路径和缺项，不猜称呼。列表、地图和搜索都严格使用当前 `circleId` 获得的人物数组，不跨圈混合。

管理页仅对圈主和管理员开放。邀请真人加入与添加未加入的人物卡是两个入口；批准加入只建立成员资格。新成员进入圈子后先看到未认领卡，可提出认领申请；管理员核对后绑定。若没有合适的卡，成员可明确新建本人卡，页面在同名或待审认领时给出提醒。误认领可由管理员解绑；确认框说明私人资料与代维护授权会清空，关系节点保留。圈主可将成员设为管理员、取消管理员或移交圈主；管理员只能移除普通成员。移交后原圈主成为管理员。普通成员和管理员可从圈子页自行退出，退出后立即失去访问权；本人提供的私人资料从圈内清除，家庭关系节点保留最少信息。

家庭关系编辑使用「谁是父母 → 谁是子女」等完整方向，提交前调用 `relation.preview` 展示新增／删除的边和可能受影响人物。已有关系可直接替换或删除。普通成员提交包含具体边变化的关系建议，管理员预览后采纳；关系、建议状态和审计原子提交，后端冲突校验失败时建议保持待处理。人物资料和邀请类自由文字建议目前没有可直接采纳的按钮，管理员需先人工处理具体事项或拒绝；尚未形成与资料变更绑定的完整闭环。管理页的操作记录展示后端返回的操作者名称、动作、时间及关系更正摘要，不展示 OPENID。

地图页使用微信原生 `<map>` 底图，可切换中国和世界视图。城市标记按国家与城市聚合人数，点击后展示该城可见人物；列表与地图使用同一批经过后端权限过滤的人物。人物资料可填写国家／地区、省／州、城市；常见城市可从预设列表选择，其余城市可在“选择城市位置”页手动将地图十字移到城市中心附近。选点由原生地图返回 GCJ-02 坐标，前端与后端都将其取整到 0.1 度后保存为城市代表点，不读取实时定位或住址。城市名已填写但尚无可用坐标时，人物仍在列表中，并计入“暂未定位”；城市权限关闭时也不返回经纬度。

本人资料页直接提供「上传／更换我的照片」入口；编辑页顶部预览照片，并由本人选择仅自己或本圈成员可见。相册 JPG 可直接使用，PNG 等可绘制图片会先在本地 Canvas 转成小于 1 MiB 的 JPEG；选图时即反馈转换失败。已有卡可单独保存照片，新建本人卡随人物卡一起保存。演示模式把照片保存在本机文件路径，写入失败会报错；云端模式将 JPEG 以 base64 交给受鉴权的 `photo.upload` 云函数，照片与可见范围同次保存，不从客户端直接写云存储。人物视图只包含 `hasPhoto`，不接收原始云文件 ID。可见人物的短期照片链接通过 `photo.urls` 每批最多 20 人渐进加载；旧云函数不支持批量动作时才逐人调用 `photo.url`，未获取到时使用文字头像。

微信分享按钮在真实小程序身份下分享一次性邀请。云端模式下，邀请页调用 `invite.code`，由已鉴权云函数向微信开放接口请求小程序码，把与分享卡片相同的令牌放入 `scene`，再将返回的 PNG 保存到小程序临时文件显示。管理员撤销或邀请被使用后，旧码对应的令牌失效。本地演示只提供“预览受邀者申请页面”，明确提示不能扫码；CloudBase 环境尚未创建，真实生成、扫码落地和跨账号使用仍待真机联调。

## 自动检查

在项目根目录运行：

```text
npm run typecheck:frontend
node --test miniprogram/tests/*.test.cjs
```

前端测试覆盖真实地图城市标记聚合、中国／世界范围、未知城市、手动选点取整、两类圈子数据隔离、隐藏城市时的经纬度过滤、以本人为起点的称呼计算、一次性邀请、分享链接与扫码 scene 的云端路由、同学圈班级字段约束、圈主任免与移交、成员退出后的访问和私人资料清理。加入后认领、关系预览和更正流程也需用页面交互及服务端测试共同验收。根目录的 `npm test` 还会运行后端、称呼引擎与项目文件检查。

## 开发者工具手工验收路径

1. 导入项目根目录，从首页进入家庭圈。确认整张关系网按辈分分层、本人星球高亮、人物连接可见；点伯父星球查看标签和详情，确认称呼与“我 → 爸爸 → 爸爸的哥哥”路径，图的代际排列不因点选而改变。
2. 家庭圈切换中国／世界原生地图。世界视图跨洲城市无法在一屏全部显示；从地图下方的城市索引选择海外城市，使地图聚焦到该城，再点标记查看人物。切回列表仍在同一个家庭圈。
3. 进入同学圈，按城市、状态、行业筛选；隐藏城市的人仍可在列表中找到，但不出现在城市点。
4. 编辑自己的城市：选一个预设城市，再手动输入另一座城市并进入地图选点页，拖动到城市中心后保存；确认地图出现新标记。编辑职业和联系方式后，在可见范围页分别关闭或开启展示；隐藏城市时地图不显示该人物的坐标，手机和微信号初始仅本人可见。
5. 管理页生成邀请，预览申请页填写姓名与身份核对说明；同学圈须写同班核对信息。申请人在首页可查看审核状态。管理员批准后，该成员先核对未认领卡、提交认领申请；管理员核准后本人卡高亮。另试「这些卡都不是我」新建本人卡及同名提示。再次用同一份邀请申请或批准另一人，应得到已使用提示。
6. 新建自己记录的圈子，首次邀请时先确认历史资料可见范围，随后升级为邀请共建。
7. 作为管理员增加一张未认领卡，建立家庭关系；新增、替换、删除关系前核对「父母 → 子女」语句和影响预览；试亲子环和互斥边，应被拒绝。提交结构化关系更正建议并采纳，核对关系网和处理状态同时变化。尝试删除关联卡时应先看到关系影响提示。
8. 管理页区分「邀请真人加入」「未认领人物卡」「已加入成员」。圈主将普通成员设为管理员，再取消；移交圈主后，确认原圈主仍可进入管理页，但不能再任免管理员。操作记录能看到操作者和关系变更摘要。误认领解绑前须看到私人资料清空提示。
9. 以普通成员或管理员身份退出圈子，确认该圈从首页消失，原人物卡的私人资料不再可见；圈主需先移交后才能退出。

新版关系图、原生地图和城市选点的核心路径已在开发者工具模拟器验证，记录见[测试报告](test-report.md)。CloudBase 环境和微信分享／扫码联调尚未完成。上线前需用真实账号在微信开发者工具与真机执行完整流程，并核对云函数部署、照片短期链接和权限规则。
