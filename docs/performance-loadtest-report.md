# 家庭网站本地并发与资源测试

测试日期：2026-10-05。业务代码版本：`aa05a98`。

## 结论

本机测试中，30～50位家人浏览均成功；突发登录和同IP游客进入会触发既有保护规则。资源占用以百MB计，但本机有16个逻辑处理器，结果不能等同于2核云服务器的吞吐能力。

## 测试环境与方法

- Windows，AMD Ryzen 7 7840H with Radeon 780M Graphics，16个逻辑处理器，可见内存39.2 GiB，Node v22.16.0。
- 独立临时SQLite数据库，100位虚构家人、4代、40个城市、50个独立普通成员账号。播种后重启为生产API配置，未放宽登录/游客限流。每个场景开始只清空临时数据库的限流计数，避免前一场景污染后一场景。
- API与压力客户端使用不同进程；API仅绑定127.0.0.1随机端口。可信代理头模拟50个不同来源IP，同IP场景另测。已有5173/5175服务和真实资料未参与。
- 浏览场景每人完成5轮访问，每轮8个真实接口请求，轮间停1秒、用户起始间隔20ms。50人同时刷新则不设置起始错开。游客读取完整家庭快照（含生日）。
- 成员资料接口验证返回100人；HTTP 200但业务ok=false计为失败。延迟包含完整HTTP响应读取；p95代表95%的请求不超过该值，并非完整页面渲染耗时。
- API内存每20ms采样RSS，事件循环每10ms采样。CPU百分比以一个逻辑核=100%计；例如400%约为4个逻辑核的CPU时间。前端Caddy由独立系统进程每50ms采样。

## 前端静态资源实测

- 使用[Caddy官方v2.11.7](https://github.com/caddyserver/caddy/releases/tag/v2.11.7) Windows版，按官方checksums.txt的SHA512验证下载包；临时运行，不安装系统服务。压测前重新构建正式前端。
- 使用部署文件相同的gzip/zstd协商和静态缓存规则；客户端请求gzip，直接统计线上压缩字节，不把解压后的大小冒充网络传输量。测试为本机HTTP/1.1，没有公网带宽和HTTPS握手开销。
- 冷缓存指客户端未缓存；服务器文件系统可能已经缓存文件。缓存组显式发送If-None-Match校验，正常使用immutable缓存时浏览器还可直接避免发请求。

## 对部署配置的解释

- 后端浏览峰值约124 MiB，登录突发约249 MiB；Caddy本轮采样峰值约111 MiB。两者为分别测量，不能把相加结果说成整机同步峰值，也未包含操作系统、Docker和构建过程。
- 2核2GB仍可作为部署起步配置；需要在目标云服务器复测。50人刷新时API单核已接近饱和，p95约1.34秒；Caddy地图压缩突发会利用多个逻辑核，不能把本机约0.2秒传完的结果照搬到2核机器。
- 50人首次读取地图资源的实际gzip正文合计约56.40 MiB。10 Mbps出口仅传这些正文的理论下限约47.3秒，尚未计入首页、照片、网络损耗。带宽是独立于服务器处理速度的限制。

## 两个已确认的使用限制

- 密码校验最多同时4个：50账号瞬时登录，4成功、46返回429；错开到10秒内登录则50个全部成功。不能用这些快速拒绝的请求宣称高登录吞吐。
- 游客入口每IP 15分钟30次：50人共用一个出口IP输入正确家庭名称，30成功、20返回429。亲戚共用Wi-Fi时可能遇到；它是当前限流规则，尚未在本次测试中修改。

## 范围与复现

- 本次不是长期稳定性、照片上传/下载、管理写入冲突或手机帧率测试。没有在2核2GB容器限额下运行，也没有模拟真实移动网络；没有据此宣称生产服务器容量已经验收。
- 本次有效API结果共4000请求，其中66个预期429；其余3934成功，无5xx/超时。前端600个请求全部按预期返回200或304。
- 运行 `npm run build`，再运行 `node scripts/loadtest-family.cjs`。后端脚本会自行创建和清理临时数据库；不要把线上数据库路径传给测试。
- 前端先下载并校验官方Caddy，然后运行 `node scripts/loadtest-static.cjs <caddy.exe完整路径>`。脚本只绑定本机随机端口，结束后关闭进程并删除临时配置。
- 原始数据：[API](performance-loadtest.json)、[Caddy](performance-static-loadtest.json)。脚本生成的密码与会话仅在测试进程之间传递，不写入报告。
