# 家庭关系与称呼模块设计

## 目标与边界

家庭圈内的一组人物和亲子、配偶、兄弟姐妹关系，形成可从任意人物观察的关系网。称呼计算只在关系明确时给出具体叫法。信息不足时保留完整关系路径，并指出要补充的字段。该模块不负责云数据库读取、圈子权限、资料访问权限或关系编辑审批；这些由服务端完成。家庭圈与同学圈不共用关系图，同学圈不调用称呼规则。

## 数据模型

- `Person.id` 是圈内人物卡的稳定 ID；姓名只用于界面，不用于合并和推理。`gender` 可为 `male`、`female` 或 `unknown`。`birthDate` 为完整公历出生日期，同年可比较月日；农历按其出生年转换后传入。旧 `birthYear` 继续兼容，同年仅有年份时不猜长幼。
- `parent_child` 明确连接父母和子女，`kind` 可标明普通、收养或继亲。父母的配偶**不会**自动变成另一位父母。
- `spouse` 明确连接配偶，区分现任与前任。前任关系保留路径，但不按现任配偶计算称呼。
- `sibling` 明确连接兄弟姐妹，`olderPersonId` 记录哪位较年长。`rankOfA`、`rankOfB` 是各自在同性别兄弟姐妹中的排行，可辅助长幼判断；只有录入目标的排行后才生成「大姨」「二姨」等排行叫法。长幼、排行与不同出生年份相冲突时拒绝计算，提示先纠正资料。共享一位普通父母且没有显式兄弟姐妹边时，可推断一条兄弟姐妹边；不会自动推断排行。
- `KinshipOverride` 按视角人物与目标人物保存圈内或个人常用叫法。个人设置优先于圈内设置；底层自动结果和路径仍保留供核对。

所有人物与关系必须先按当前 `circleId` 从服务端过滤和授权，然后才能传入 `resolveKinship`。该纯函数不能充当访问控制。

## 计算过程

1. 检查人物 ID、关系端点和亲子有向环。无效数据返回 `invalid`，不尝试给称呼。
2. 将显式关系转换为双向可走的图边；符合条件时补出共享父母的兄弟姐妹边。边保留亲子类型、配偶状态、长幼和排行信息。
3. 从当前视角做广度优先搜索，找出到目标的最短路径。每一步生成可读标签，组合为「我 → 妈妈 → 妈妈的姐姐」。同长度的路径最多保存 32 条；超过上限返回 `ambiguous`，要求核对，避免忽略冲突路径。
4. 按路径模式和所需信息应用第一版规则。多条路径如果得到同一称呼，使用该称呼；出现不同叫法或其中一条无法确定时返回 `ambiguous`。路径可走但规则未覆盖时返回 `pending`。
5. 最后叠加当前视角的个人或圈内常用叫法。`term` 用于展示，`calculatedTerm` 保留规则结果；`status` 不被自定义文字改变。

## 第一版规则范围

- 本人、父母、子女、现任配偶、兄弟姐妹；兄弟姐妹须有性别与长幼信息，才能区分哥哥、弟弟、姐姐、妹妹。
- 父系和母系祖父母、孙辈与外孙辈。
- 父母的兄弟姐妹及其配偶：父亲的哥哥为伯父（别称伯伯），弟弟为叔叔；父亲的姐妹为姑姑；母亲的兄弟为舅舅，姐妹为姨妈（别称姨母）。姨的排行只有明确记录后才用于大姨、二姨等叫法。
- 兄弟姐妹的子女、兄弟姐妹的配偶、子女的配偶、配偶的父母。
- 父亲的兄弟的子女为堂兄弟姐妹，其他父母手足的子女为表兄弟姐妹；目标人物性别与双方长幼明确后才能具体显示堂哥、表妹等叫法。

收养、继亲、同父异母或同母异父，以及暂未覆盖的长路径，第一版展示已知路径并提示确认。方言、各家习惯叫法由自定义设置承载，不改写底层亲属事实。

## 展示与错误处理

页面应优先显示 `term`，有 `alternatives` 时可一并展示常见别称；点击称呼能看 `path.display`。`pending` 应列出 `missing` 或 `reason`，并提供补充或纠错入口。`ambiguous` 允许查看 `paths` 的各条路径，不宜选一个自动当作已确认。`unrelated` 显示「尚未连接关系」，不显示「远房亲戚」。`invalid` 应通知管理员修正错误关系。

测试覆盖视角切换、伯父和叔叔、姨妈及排行、长幼资料冲突、祖孙、共享父母推断、堂表亲、缺少长幼或性别、收养与继亲、前配偶、父母配偶不自动认亲、多路径冲突、自定义叫法、亲子循环和不相连人物。


## 按出生日期比较长幼（2026-10-03）

新增页不再要求排行。生日含完整出生年份时，birthDateForBirthday 校验并把阳历或农历转换成实际公历出生日期。缺年份、同日出生、无效日期、历表范围外不猜；年度生日提醒转换不用于年龄比较。旧 olderId 和排行保留，与出生日期矛盾时显示关系待核对。不会根据已录入人数推断“大姨、二姨”。
