# 微信小程序前端设计与本地演示

## 运行方式

用微信开发者工具导入项目根目录。`project.config.json` 指向 `miniprogram/` 和 `cloudfunctions/`；本机可在被 Git 忽略的 `project.private.config.json` 配置测试 AppID。没有 `miniprogram/config.ts` 中的 CloudBase 环境 ID 时默认使用本地演示数据。演示资料只保存在当前开发者工具或设备，可在「我的」恢复初始样例。真实云端使用 `miniprogram/services/api.ts` 的 `invoke({action,payload})` 调用 `api` 云函数。

## 页面和导航

首次进入显示「微信手机号登录」。真实环境需用户点微信授权按钮取得一次性 `code`，云函数向微信换号；有效期内再次打开自动进入。本地演示的同名按钮用固定模拟号码，不调用微信换号。未登录访问「亲友录」或「我的」会回到登录页；受邀链接可先看邀请摘要，申请前需登录。登录页会在授权后返回该邀请。

底部只保留「亲友录」「我的」。亲友录按「家人录」「同窗录」分开展示，并放新建入口、申请状态和近期生日；卡片上的人数按已录入人物数统计，与详情列表和关系图一致，不因某人是否登录而变化。我的只放一份个人资料入口，以及创建者或管理员可见的管理入口，不重复列出已加入记录。普通成员没有管理模块。成员退出入口位于相应家人录或同窗录详情页，创建者须先移交管理权。

家人录使用「亲缘图」「家人簿」「天南海北」三个入口，分别展示按辈分分行的关系图、人物列表和城市地图；同窗录使用「同窗簿」「天南海北」。城市入口统一配文「看看大家在哪里」。本人节点高亮，点击人物显示称呼及从本人出发的路径。点选不会使其他人物变糊或自动滚动页面；搜索时保留完整关系链。世界视图默认显示基于真实地理数据的全球概览和城市标记，点城市后进入微信原生 `<map>` 详细地图；中国视图直接显示原生地图。列表人数、地图人数和未上图原因同时显示。城市由离线目录按国家／地区、省／州、城市逐级选择，未收录城市可手填并标为待定位；不读取实时位置或住址。

## 一份个人资料

`/pages/profile/index` 是本人的唯一编辑入口，可在未加入任何记录时填写姓名、昵称、性别、城市、生日、近况、学校、行业、职业、联系手机号、微信号和照片。姓名、城市和生日填全后才能加入或创建本人关系节点。生日可选阳历、农历与闰月，出生年份可选；表单即时显示下一次对应的公历日期。已关联的家人和同学人物节点读取同一份账号资料，改一次会同时更新各处；亲属关系、同辈排行仍属于具体家人录。

照片在本地 Canvas 转成不超过 1 MiB 的 JPEG，去除拍摄位置等元数据；云函数再次校验文件和权限。本人即使尚未加入任何记录也可上传照片。其他已加入同一份记录的成员可以查看该人物的照片和已填写资料，申请未通过者不能访问。照片的云存储文件 ID 不直接返回给页面，人物图和列表按需获取短期 URL。

管理员添加家人或同学时，先填姓名、关系（家人）、城市和生日，照片及联系方式等按需展开。新增时只填一次手机号，同时保存为联系电话与本人核对号码；已有资料的两类号码不同则继续独立保留。家人录已有人的情况下，默认选一位已记录家人，再选择爸爸、妈妈、兄弟姐妹等关系；不清楚时可显式开启“稍后补关系”，先显示在“关系待补充”区。首位家人无需关系。创建人物和关系在后端同一事务保存。称呼由事实关系计算，不要求管理员预先填写相对某人的“伯父”“姨妈”。手机号匹配只帮助已通过本人申请及管理员审核的人关联已有节点，不能单凭管理员预填号码让账号加入记录。若尚无预录资料，受邀者先在唯一的「我的资料」里填全姓名、城市和生日，再于邀请页补充身份说明；加入申请使用服务端保存的账号资料，不能在申请页另维护一份。管理员审批家人加入时，若选「新增资料」，已有家人时默认选择首条关系，也可显式开启“稍后补关系”；若选「使用已有资料」，原有关系保留并展示原卡与申请人资料供核对。班级邀请要求填写同班核对说明。资料填错可由本人修正；关系归属错误由管理员核对处理。

## 生日和日历

亲友录首页预览未来 30 天的生日，日程页查看未来一年；本人生日不出现在自己的提醒中。同一登录账号若在多个家人录或同窗录有节点，只提醒一次，事件仍能进入其中一张人物卡。列表显示原始历法和下一次公历日期；跨年后自动重新计算。前后端共用 `packages/lunar-calendar/src/index.ts` 的香港天文台 1901–2100 年公农历对照表，避免设备 `Intl` 实现不同造成日期偏差；太阳历的 2 月 29 日和农历闰月按生日规则处理。

## 管理与邀请

管理页只对创建者和管理员开放，提供添加人物、关系编辑、管理员权限管理、一次性邀请、申请审核和操作记录。默认「人物」页签显示可搜索的人物列表，每行直接提供「编辑资料」「编辑关系」；「关系」页签先显示已有关系，按需展开编辑器；申请与建议位于「待办」，角色、移出及操作记录位于「设置」。新增和修改关系使用页面内预览，保存时直接提交服务端校验；删除保留简短确认。普通成员可提出更正建议。微信分享和小程序码使用同一枚 72 小时一次性邀请令牌，可撤销。本地演示可以预览申请页，但不能生成供另一微信扫码的真实码。

创建者可设置管理员并发起管理权移交；管理员只管理权限以下的成员。管理员可直接更正本记录内任何人物资料和关系；已关联人物的资料更正不写入对方的账号资料或其他记录，页面简短提示「此处修改只影响本录」。本人随后更改账号资料的同字段时，个人资料更新优先。管理页隐藏只是交互控制；服务端仍按角色和成员身份鉴权。正式云函数入口还要求已通过微信手机号登录，避免直接调用云函数绕过页面门禁。

## 本地验证

在项目根目录运行 `npm test`。测试覆盖关系图、地图、逐级城市选择、登录和手机号关联、共享资料、邀请申请、角色权限、照片和生日换算。开发者工具中的实际页面截图与已验证操作见[测试报告](test-report.md)。本地演示无法证明真实微信手机号授权、云数据库规则、分享扫码、跨微信账号权限和真机地图表现；这些需要配置 CloudBase 环境后验收。


本地开发默认关闭 `compileHotReLoad`，使用正常编译，避免开发者工具连续热更新时组件样式注册暂时不一致。修改后的页面以冷编译和模拟器截图共同验收。


## 浏览与管理分开（2026-10-03）

底部“亲友录 / 我的”使用自定义 tabBar，文字固定为 17px，每项至少 50px 高，预留底部安全区。各 tab 页在显示时同步选中状态，失败或重复点击不会提前改变高亮。

从亲友录的列表、关系网、地图和生日进入人物详情，管理员和普通成员看到相同的只读资料。自己的资料仍可进入唯一账号资料页修改；他人的资料只提供联系和“备注名（仅自己可见）”。备注在详情页内编辑、保存或清除，不使用难读的输入弹窗，也不改变对方的姓名和关系。备注读取失败会单独显示重试，不把失败当作空内容保存。

他人的编辑、照片更换和人物删除入口集中在“我的 → 管理 → 人物”；关系修改在同一管理页进行。普通成员直接打开他人的编辑页会明确拒绝，不显示可以填写但无法保存的表单。


## 关系图、备注名和添加流程（2026-10-03）

关系图采用米白底、柔和头像卡、细线连接，同辈在一层，本人高亮。点人物立即出现固定小浮卡，再点同人、图中空白或关闭按钮收起；按触点位置上下择位，不滚页、不加遮罩或模糊。异步照片不得重开已收起的卡。

备注通过 person.remark.list 单独加载；列表、地图、关系图、详情主名均显示备注名，详情保留原名，两种名字均可搜索。关系计算使用原始人物，备注不改变图中排序。历史 200 字内容保留，失败显示原名，可重试，旧会话响应不得串号。

新增页可展开“怎么添加？”：管理员可先记录没注册的妈妈并连接自己；远亲可通过中间家人连接，不清楚可先保存后在管理页补边。姓名、城市、生日仍须完整。出生年份移到生日旁，取消手填排行和额外长幼选择器，旧数据保留。网络不确定重试沿用原创建请求，关系选择变化时明确提示按上次关系保存，之后可在管理页更改。


## 入口表达（2026-10-03）

家人录使用“亲缘图 / 家人簿 / 天南海北”，同窗录使用“同窗簿 / 天南海北”；“天南海北”的说明统一为“看看大家在哪里”。城市视图默认中国；海外人数单独说明，世界视图可查看全部已有位置，资料总人数保持一致。

当前保持免费，收费方案暂缓；本轮不开发支付、会员或按套餐限制人数的入口。


## 管理与加入简化（2026-10-03）

成员菜单只保留设／取消管理员及移出成员；更换创建者单独折叠在设置页，必须选接收人并等其确认。日常界面不再展示解除账号关联，操作记录默认收起；实际服务端角色和越级限制保持有效。本人识别使用“这是我／等待管理员确认”。

新建时直接选择家人或同学并命名，取消自己记录／共建前置问题，之后生成邀请时按现有规则开启邀请。邀请页面用一段说明表达审核范围，直接生成单次三天邀请。再次打开旧邀请，先核对当前账号是否已加入，或恢复该邀请的本人申请；失效邀请的访客可返回首页，不能读成员资料。
