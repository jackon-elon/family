# 入圈、认领与管理流程产品复核

日期：2026-10-02

性质：本地修复后的产品复核。页面、演示数据适配器与后端服务已实现的部分仍须在真实 CloudBase 环境用多个微信账号验证。

## 核心判断

微信登录、申请加入圈子、认领人物卡、建立亲属关系是四件不同的事。注册或申请加入时不要求填写「我是某人的伯父」这类称呼。家庭圈记录两位具体人物间的亲子、配偶或兄弟姐妹事实，再相对于当前成员本人卡计算称呼。加入审核通过只授予访问权，不自动创建或认领人物卡。

家庭圈关系网按辈分展示可见人物，本人卡高亮。点击人物查看其标签、称呼和关系路径，不切换整张图的中心。尚未认领本人卡的成员可以先浏览已授权的资料，再核对已有卡或新建本人卡；系统不凭姓名猜测身份或称呼。

## 本轮已实现的本地流程

1. **申请与状态**：受邀者填写圈内常用姓名和身份核对说明；同学圈必须提供同班核对信息。申请人只能看有限的邀请预览和自己的审核中、已通过、已拒绝或已失效状态。邀请失效时提示联系管理员重新邀请。管理员在管理页审核真人身份，批准入圈与认领卡分开。
2. **入圈后认领**：圈子页先列出未认领卡供成员选择「这是我」，管理员随后审核认领；如果都不是，成员可明确选择新建本人卡。编辑本人卡前会提示同名未认领卡；有待审认领时阻止新建，避免同一人出现两张卡。同名不会自动绑定、合并。管理页可解绑错误认领，并在确认前说明私人资料与代维护授权会清空，关系节点仍保留。
3. **管理员动作分开**：管理页分别呈现「邀请真人加入」「添加未加入的人物卡」「成员账号」「认领审核」「整理关系」。邀请只产生申请入口，预建人物卡不给对方访问权，移出成员撤销其访问权而保留最少的关系节点。管理员不能凭管理身份查看或修改已认领成员隐藏的电话、城市等字段。
4. **关系录入与纠错**：亲子表单明确「父母 → 子女」方向，新增、替换、删除前可请求 `relation.preview` 核对边变化与可能受影响人物。后端拦截自我关系、同一人物对的互斥关系、亲子循环和确定的代际矛盾。成员提交结构化关系更正建议，管理员预览后采纳时，关系变更、建议状态与操作记录一并提交；失败时建议保持待处理。旧的纯文字关系建议不能直接标成已采纳，须重新给出具体改动。
5. **操作记录**：管理员可见操作者名称、时间、动作和关系改动摘要；服务端不向页面暴露操作者 OPENID。关系预览的「受影响人物」表示可能改变的关联范围，不等同于逐人精确计算后的新称呼。

## 再次审核后的修复

- **可用性**：圈子、人物、编辑、管理、邀请和隐私页在关键读取失败时显示错误及重试入口，避免把网络失败当成“没有关系／没有管理员”。首页可展开最近 20 条加入申请；已批准但本人已退出或被移出的历史申请不再提供进圈按钮。旧的活跃邀请可在再次打开邀请页时找到并撤销，原口令不会重新暴露。
- **便捷性与数据一致性**：创建圈子和人物卡使用一次请求标识，响应丢失后的重试返回原记录；同一成员的其他待审加入申请会在批准后失效，成员退出或被移出时待审认领也同步失效。人物姓名不能被清空，删除人物前还会检查实际关系边。页面阻止关键按钮重复提交。
- **隐私与费用**：照片无论原格式都在本地重编码，服务端再次剥离 JPEG 元数据并拒绝异常尺寸。公开接口不能绕过云函数直接绑定照片文件；上传过程中会重新核对授权，每个微信账号在一个 24 小时配额窗口最多尝试上传 20 张照片。辅助文字字号、对比度和分段按钮触达区域也已调整。

## 仍需补齐或验证

- **云端邀请**：微信分享和小程序码的服务端接线已使用同一份 72 小时、一次成功批准的邀请令牌；本地演示不生成可扫码的真码。尚无 CloudBase 环境，因此小程序码生成、扫码落地、分享卡片、真机及跨账号并发审批未验证。
- **误操作恢复**：解绑会清空人物卡私人资料，当前只有确认提示和操作记录，没有撤销或恢复入口。关系删除、成员移出也缺少可靠的短期恢复方案；上线前需定备份、恢复时限及操作责任。
- **当事人通知**：审核与认领状态可在页面查看，尚无微信订阅消息或关系更正、解绑、移出成员后的主动通知。涉及已认领人物的关系争议需要明确反馈和告知路径。
- **复杂关系与重复卡**：再婚、继亲、收养、离异等尚无专门数据类型或安全的称谓规则。重复人物卡目前只提示，不提供合并；合并应处理关系边、认领、私人资料及撤销路径，不能按姓名自动执行。
- **影响预览精度**：当前预览显示新增、删除的边和可能受影响的人物范围；上线前应针对较大关系图复核可读性。确实无法由基础亲子、配偶或兄弟姐妹边表达的关系，应显示待核实，不强行套用普通血缘称呼。
- **资料与邀请建议**：结构化关系建议已形成「实际修改关系 + 更新建议状态 + 审计」的原子闭环。人物资料和邀请类自由文字建议目前不能直接标记为已采纳，只能先由管理员人工处理具体事项，或拒绝并请成员重提；后续需把具体资料变更、处理状态与审计关联起来。

## 管理员权限边界

- 管理员可新增和修正未认领人物卡的姓名、性别、排行等最少资料；可审核加入、认领，添加或纠正关系，邀请和移出普通成员。
- 已认领成员的照片、城市、手机号、微信号等由本人维护。管理员只有在本人按字段授权后才能代维护授权字段，不能替本人扩大资料可见范围。
- 普通成员可编辑本人资料、提出他人资料或关系的更正建议。关系建议进入管理员待处理队列，不直接改写全圈图。

## 验收场景

1. 管理员已建立并连好「张三」卡；张三受邀入圈后申请认领该卡，管理员核准，系统不再创建第二张张三卡。
2. 被转发邀请的人填了圈内已有的姓名但未通过身份核对；该申请人始终看不到圈内人物、地图或联系方式。
3. 新人先入圈、暂未认领卡；关系图不把陌生人物自动当作本人，也不猜测相对于本人的称呼。
4. 管理员把亲子方向填反：保存前能读懂「父母 → 子女」和影响范围；保存后可替换关系，相关称呼按新图重算。结构化建议采纳失败时仍保持待处理。
5. 管理员误认领解绑时必须看到私人字段清空提示，记录可追溯；恢复方案在正式上线前补齐。
6. 管理员移出成员后该账号立即失去访问权；关系图保留不含私人资料的必要节点。真实云端用多个账号再次验证隔离与并发。
