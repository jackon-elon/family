# 测试计划

## 第一层：本地自动化

- 亲属称谓与关系图：父母两侧、长幼、排行、从本人卡到所选人物的路径、信息缺失、多条路径和循环数据；验证祖辈、父母及其兄弟姐妹、本人及堂表兄弟姐妹分别同层，本人高亮，矛盾或断连节点不乱归层，搜索不破坏代际计算。
- 后端：圈子隔离、跨圈管理员越权、邀请过期／撤销／重复批准、陌生人申请前的可见范围、移除后的访问、手机号／微信号隐藏、长辈授权撤销；城市坐标成对校验、取整、城市隐私过滤及移除后清除。
- 加入与认领：申请只填写姓名和身份核对说明、同学圈必须填写同班说明；拒绝旧客户端随申请提交 `claimPersonId`；批准入圈后只授予成员资格，不自动认领或创建人物卡；`join.mine` 仅返回本人申请及邀请失效状态；成员申请认领已有卡、管理员批准／拒绝、本人查询认领状态、同一人物并发认领与误认领解绑后的私人资料清理。
- 关系更正：`relation.preview` 不落库，新增／替换／删除展示边变化和受影响人物；同一人物对互斥边、亲子环及确定的代际矛盾被拒绝；关系建议须带结构化改动，采纳时关系、建议状态与审计一起提交，校验或并发冲突失败时建议保持待处理。审核日志不暴露 OPENID，显示操作者和改动摘要。
- 小程序码云函数：用模拟 SDK 验证仅本圈管理员能生成有效邀请的小程序码、`scene` 与微信分享同 token、二维码内容为 PNG；真实生成与扫描留待云端联调。
- 地图与选点：微信原生城市标记按国家／城市聚合，中国／世界范围、未知城市列表回退、地图中心选点的 0.1 度取整及保存。
- 编译检查：前端 TypeScript、云函数构建、项目配置与文件引用。

## 第二层：本地交互

用演示数据走通建家庭圈和同学圈、按辈分显示整张关系网与本人高亮、点选人物后的称呼和关系路径、原生地图与列表一致、预设及手动选择城市中心、城市聚合。完成「管理员预建未认领卡 → 受邀者申请并查看状态 → 管理员批准入圈 → 受邀者选择已有卡申请认领 → 管理员核准」；另走「这些卡都不是我 → 新建本人卡」和同名提示路径。管理员分别操作邀请、人物卡、成员，检查移出与解绑的影响提示。录入亲子关系时核对方向，预览并新增、替换、删除关系；成员提交结构化更正建议，管理员采纳后图和状态同步变化。手动选择一座预设以外的城市，确认地图出现标记；关闭城市可见范围后确认其他成员的地图与列表不显示地点。此层使用模拟身份，属于页面和流程验证。中国底图、世界底图、城市选点和关系图在开发者工具模拟器中分别留截图并记录加载结果；模拟器通过后再做真机复核。

## 第三层：接入真实微信后

至少使用圈主、普通成员、未受邀者三个微信账号，在微信开发者工具和真机上验收：同一令牌的微信分享与小程序码扫码落地、一次性使用的并发审批、入圈后认领与误认领更正、跨圈数据隔离、本人资料可见范围、移除成员后的即时拒绝、中国与世界原生地图、任意城市手动选点及城市权限、云存储图片权限。记录每项测试账号、步骤、预期、实际与截图。云环境未就绪前，此层标记为待测，不能声称上线验证完成。

## 上线门槛

自动化测试通过；第一版验收场景在真机通过；误解绑、误删关系和移出成员的恢复方案已确定并验证，必要通知与特殊家庭关系的上线范围已定稿；小程序隐私指引、类目和备案按微信平台要求完成；云环境权限与费用告警已配置；上传开发版本并完成平台审核。
